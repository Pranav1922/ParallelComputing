# Data Schema

Rule from the manual: preserve raw measurements; compute derived metrics from raw data, never enter them by hand.
So there are two layers:

- **Raw** — `results/raw/<campaign_id>/`. Written once by the runner, append-only while running, set read-only
  (`chmod 444`) when the campaign finishes. Never edited. A rerun creates a new campaign directory.
- **Derived** — `results/derived/<campaign_id>/` and `results/figures/<campaign_id>/`. Fully regenerated by `python -m schedlab analyze <raw dir>`. Safe to delete.

No measured value appears in this document. Example rows use `<placeholders>`.

---

## 1. Raw: `runs.csv`

One row per (instance, algorithm, repeat).

| Column | Type | Unit | Meaning |
|---|---|---|---|
| `run_uid` | str | — | Unique: `<campaign_id>-<sequence>`. |
| `campaign_id` | str | — | `<UTC timestamp>-<config name>-<config_hash[:8]>`. |
| `sub_problem` | str | — | Owner of the algorithm: `BASE` (heuristics), `S01`, `S02`, `S03`. |
| `workload_class` | str | — | `regular`, `irregular`, `heterogeneous`, `irregular_hetero`, or an OOD label. |
| `family` | str | — | `layered` or `forkjoin`. |
| `split` | str | — | `val`, `test_id`, `test_ood`. (`train` rows are never written here.) |
| `instance_id` | str | — | Human-readable id. |
| `instance_hash` | str | — | SHA-1 of edges and cost bytes. |
| `instance_seed` | str | — | The `SeedSequence` entropy tuple as text. |
| `problem_size` | int | tasks | `n`. |
| `n_edges` | int | edges | `e`. |
| `platform` | str | — | `homog` or `hetero`. |
| `resource_count` | int | processors | `m` (simulated). |
| `algorithm` | str | — | e.g. `FCFS-EAT`, `HEFT`, `GA`, `RL`, `ADAPTIVE`. |
| `algo_config_hash` | str | — | Short hash of the algorithm's parameters. |
| `algo_seed` | int | — | Algorithm RNG seed; for `RL`, the training seed. `NA` for deterministic heuristics. |
| `model_id` | str | — | SHA-256 prefix of the model file for learned methods; else `NA`. |
| `run_id` | int | — | Repeat index, from 0. |
| `makespan_sim` | float | `sim_tu` | **Raw (simulated).** `max finish`. |
| `busy_time_sim` | float | `sim_tu` | **Raw (simulated).** `Σ_t cost[t, proc[t]]`. |
| `scheduling_time_s` | float | s | **Raw (measured).** Wall-clock time of the whole scheduler call. |
| `decision_time_s` | float | s | **Raw (measured).** Feature extraction + selection only (`S03`); network forward passes only (`S02`); else `NA`. |
| `decision_count` | int | — | Number of decisions made (`n` for RL; 1 for `ADAPTIVE`). |
| `fitness_evals` | int | — | Schedule evaluations performed (GA family; 6 for `TRY-ALL`; 1 for a heuristic). |
| `peak_rss_kb` | int | kB | Process peak resident set size when the row is written (`resource.getrusage`; macOS reports bytes and Linux kB, so the runner converts to kB). Process-wide and monotone: an upper bound, not per-run. |
| `serial_best_sim` | float | `sim_tu` | Instance invariant: `min_p Σ_t cost[t, p]`. |
| `lower_bound_sim` | float | `sim_tu` | Instance invariant: see §4. |
| `valid` | int | — | 1 if `validate()` returned no violations. |
| `status` | str | — | `ok`, `invalid`, `error`, `timeout`. |
| `error_msg` | str | — | First line of the exception or first violation. |
| `threads` | int | — | OS threads used by the scheduler (1). |
| `workers` | int | — | Concurrent campaign worker processes when this row was measured. |
| `hardware_id` | str | — | Key into `manifest.json` hardware block. |
| `time_unit` | str | — | Always `sim_tu`. |
| `timestamp_utc` | str | — | ISO 8601. |

Failed runs still produce a row (`status ≠ ok`, measurement fields `NA`). This includes `invalid` rows: an infeasible
schedule has no trustworthy makespan or timing, so those are `NA` and the first violation goes in `error_msg`. They are never dropped; the analysis counts
and reports them.

Missing, unavailable or inapplicable values are the literal string **`NA`**, in raw and derived files alike. They are
never written as 0 and never left blank. (`pandas.read_csv` reads `NA` as missing by default.)

`Student_ID` and `Batch_ID` are deliberately **not** in the raw file. They are not measurements, they are not yet
confirmed, and raw files are immutable. They are joined in at analysis time (§5).

Example (placeholders, not data):

```
run_uid,campaign_id,sub_problem,...,algorithm,algo_seed,run_id,makespan_sim,busy_time_sim,scheduling_time_s,...
<campaign>-000001,<campaign>,S01,...,GA,<seed>,0,<float>,<float>,<float>,...
```

## 2. Raw: trace files

**`ga_trace.csv`** — one row per generation for `GA` variants, and one row per `population` evaluations for
`RANDOM-SEARCH` and `HILL-CLIMB` (same cadence). Always written; header only when a campaign has no S01 runs.
`run_uid, generation, fitness_evals, elapsed_s, best_makespan_sim, mean_makespan_sim`

**`rl_training.csv`** — one row per logged update (written by `train-rl`, copied into the campaign directory).
`model_id, train_seed, update, episodes, elapsed_s, mean_return, batch_ratio_vs_heft, val_ratio_vs_heft, is_best_checkpoint`

**`selector_decisions.csv`** — one row per `ADAPTIVE` decision.
`run_uid, log_n, par_ratio, depth_ratio, edge_density, work_cv, work_skew, cp_ratio, het_machine, het_affinity, selected_policy, second_policy, fallback_used`

The oracle policy is not stored here; the analysis derives it from the heuristics' rows in `runs.csv`.

## 4. Derived metrics

Computed in `analysis.py` only.

| Metric | Formula | Notes |
|---|---|---|
| `cp_min` | Longest path through the DAG using `min_p cost[t, p]` per task | |
| `work_lb` | `Σ_t min_p cost[t, p] / m` | |
| `lower_bound` | `max(cp_min, work_lb)` | A valid lower bound on `Cmax`; loose on `hetero`. |
| `serial_best` | `min_p Σ_t cost[t, p]` | **The speedup baseline.** |
| Speedup | `serial_best / makespan` | Baseline: sequential execution on the best single simulated processor. |
| Efficiency | `Speedup / m` | Can exceed 1 on `hetero`; see methodology §8. |
| Utilization | `busy_time / (m · makespan)` | |
| Normalised makespan | `makespan / lower_bound` | ≥ 1. |
| Improvement vs X | `(makespan_X − makespan) / makespan_X` | X ∈ {`FCFS-EAT`, `HEFT`, best heuristic on the instance}; X is always named in the column. |
| Regret | `makespan / makespan_VBS − 1` | `VBS` = min over the six heuristics on that instance. |
| Break-even `τ*` | methodology §5.3 | seconds per `sim_tu`. |

Aggregation order: repeats → instance (mean; GA also min) → cell or class → overall. Confidence intervals resample
instances.

### 4.1 Aggregation of comparisons (audit of 2026-10-17)

Notation: `C_A,i` = simulated makespan of algorithm `A` on instance `i`, the **mean over its repeats or algorithm
seeds** (primary value). `GA-BEST-OF-SEEDS` uses the minimum over GA's seeds instead and is charged the sum of their
optimization times. `BEST-HEURISTIC` = `min` over the six heuristics on instance `i` (= `VBS`). `r_i = C_A,i / C_B,i`.

| Reported name | Formula | Where |
|---|---|---|
| `paired_impr_vs_B_mean`, `improvement_mean` | `mean_i (C_B,i − C_A,i) / C_B,i` = `1 − mean_i r_i` | summary, `s01_paired.csv`, G3 (per instance) |
| `improvement_geomean` | `1 − exp(mean_i ln r_i)` | `s01_paired.csv` |
| `ratio_median`, `ratio_q25`, `ratio_q75`, `ratio_min`, `ratio_max` | order statistics of `r_i` | `s01_paired.csv` |
| `ratio_ci95_lo/hi` | 2.5 / 97.5 percentiles of `mean r` over 10,000 bootstrap resamples of instances (seed 20261017) | `s01_paired.csv` |
| `better / tie / worse` | `r_i < 1`, `|r_i − 1| ≤ 1e-12`, `r_i > 1` | `s01_paired.csv` |
| `wilcoxon_p` | Wilcoxon signed-rank on paired `(C_A,i, C_B,i)`, zero differences dropped; **only** for `GA` vs `BEST-HEURISTIC` | `s01_paired.csv` |
| `cmax_over_lb_mean_of_instances` | `mean_i C_A,i / LB_i` | summary, G1 (median and IQR) |

These statistics are not interchangeable. In the S01 pilot, `GA` vs `FCFS-EAT` gives `improvement_mean` = 20.548%
(the earlier report's "20.6%" was this statistic, double-rounded via 20.55; 20.5% is correct), `improvement_geomean` = 23.6%, and
`1 − ΣC_GA / ΣC_FCFS` = 16.8%. The 29.2% obtained from `1 − mean(C_GA/LB) / mean(C_FCFS/LB)` (1.181 / 1.668) is a
ratio of two aggregate means, each weighted by `1/LB_i`, and is not a paired improvement; it is not reported.

## 5. Derived: `master.csv` (the manual's format)

One row per raw row, with the manual's 19 column names exactly, then extras.

| Manual column | Source |
|---|---|
| `Student_ID` | `configs/identity.toml`, by `sub_problem`. Placeholder `STUDENT_ID_UNCONFIRMED` until confirmed. |
| `Batch_ID` | `configs/identity.toml`. Placeholder `BATCH_ID_UNCONFIRMED` until confirmed. |
| `Workload` | `workload_class` |
| `Dataset` | `instance_id` |
| `Problem_Size` | `problem_size` |
| `Algorithm` | `algorithm` |
| `Parallel_Model` | constant `SIM-LIST-SCHED` (simulated non-preemptive list scheduling) |
| `Hardware` | `SIM:<platform>` — the simulated platform. The real host is in `Host_Hardware`. |
| `Resource_Count` | `resource_count` |
| `Threads` | `threads` |
| `Execution_Time` | `makespan_sim` — **simulated time units, not seconds** (see `Time_Unit`) |
| `Speedup` | derived |
| `Efficiency` | derived |
| `Communication_Time` | `NA` — not modelled |
| `Synchronization_Time` | `NA` — not modelled |
| `Scheduling_Time` | `scheduling_time_s` — measured seconds |
| `Memory_Use` | `peak_rss_kb` |
| `Energy_if_available` | `NA` |
| `Run_ID` | `run_uid` |

Extra columns: `Time_Unit`, `Scheduling_Time_Unit`, `Repeat`, `Error`, `Timing_Outlier` (1 if scheduling time exceeds
Q3 + 3·IQR within its algorithm × size × processor-count group; flagged, never removed), `Speedup_Baseline` (constant text naming the baseline), `Sub_Problem`, `Split`, `Platform`,
`Algo_Seed`, `Instance_Hash`, `Lower_Bound`, `Norm_Makespan`, `Utilization`, `Improvement_vs_FCFS`,
`Improvement_vs_HEFT`, `Improvement_vs_BestHeuristic`, `Regret_vs_VBS`, `Decision_Time`, `Fitness_Evals`,
`Host_Hardware`, `Status`.

All 19 fields the manual requires are present, with the manual's spelling and order. `analyze` prints a warning on
every run while either identifier is still a placeholder, and `analyze --final` refuses to write `master.csv` until
both are confirmed.

`Execution_Time` and `Scheduling_Time` are in different units. The analysis code never adds them, and the
`Time_Unit` column travels with the file so a class-level merge cannot silently mix simulated and measured times.

## 6. Configuration and manifest format (`configs/*.toml`)

```toml
[campaign]
name = "full"
seed = 20261011
workers = 1

[workload]
sizes = [50, 100, 200]
processors = [2, 4, 8]
classes = ["regular", "irregular", "heterogeneous", "irregular_hetero"]
instances = { train = 30, val = 5, test_id = 10, test_ood = 10 }
ood = ["ood_size", "ood_procs", "ood_struct", "ood_cv"]

[run]
splits = ["test_id", "test_ood"]
algorithms = ["FCFS-EAT", "FCFS-EFT", "SPT-EFT", "LPT-EFT", "HEFT", "MINMIN", "GA", "RL", "ADAPTIVE", "ADAPTIVE-TOP2", "TRY-ALL"]
timing_repeats = 3
timeout_s = 600

[ga]
population = 60
max_evals = 6000
tournament = 3
crossover_prob = 0.9
key_sigma = 0.15
mutations_per_chromosome = 1.0
elite = 2
seeds = [0, 1, 2]
seed_heuristics = ["HEFT", "MINMIN", "FCFS-EAT"]

[rl]
train_seeds = [0, 1, 2]
hidden = 64
lr = 3e-4
batch_episodes = 16
entropy_coef = 0.01
max_updates = 3000
max_minutes = 45
val_every = 100

[adaptive]
portfolio = ["FCFS-EAT", "FCFS-EFT", "SPT-EFT", "LPT-EFT", "HEFT", "MINMIN"]
max_depth = 4
novelty_margin = 0.10
```

Identifiers live in their own file, read only by `analyze`:

```toml
# configs/identity.toml — placeholders; do not guess. Replace when confirmed for this CS 15 submission.
batch_id = "BATCH_ID_UNCONFIRMED"
[student_id]
BASE = "STUDENT_ID_UNCONFIRMED"
S01 = "STUDENT_ID_UNCONFIRMED"
S02 = "STUDENT_ID_UNCONFIRMED"
S03 = "STUDENT_ID_UNCONFIRMED"
```

As implemented (M2), `[workload].instances` lists the per-cell count for every split to generate, `[run].splits`
selects which of them are scheduled, and the `[ga]`, `[rl]` and `[adaptive]` sections are added in their milestones.
`pilot.toml` has the same keys with the smaller values from methodology §6; `cost_probe.toml` measures heuristic
scheduling time at campaign sizes. Ablations are separate small config files
that change one section.

## 7. Reproducibility mechanisms

- Every random draw comes from a `numpy.random.Generator` derived from `SeedSequence([campaign_seed, purpose, ...])`.
  No global RNG, no time-based seeds.
- Derived S01 outputs (`results/derived/<campaign>/`): `s01_paired.csv` (§4.1; per split and, with more than one
  split, `all`; rows: every S01 method and `GA-BEST-OF-SEEDS` vs `FCFS-EAT`, `HEFT`, `BEST-HEURISTIC`, and `GA` vs
  each other S01 method) and `s01_overhead_quality.csv` (per method and problem size: median measured optimization
  time, median HEFT time and their ratio, paired improvement vs `HEFT` and best heuristic, share of instances better
  than `HEFT`, and the **hypothetical** median break-even `τ*` of methodology §5.3, `inf` where no gain).
- Figures (`results/figures/<campaign>/`), each as PDF, SVG, a per-instance or per-run CSV and a plotted-summary CSV:
  G1 `g1_makespan_vs_size` (Cmax/LB vs n), G2a `g2_opt_time_vs_size` (measured seconds vs n, per run),
  G2b `g2_convergence` (best-so-far Cmax / HEFT vs evaluations on a 100-evaluation grid ending at the budget; step
  function of `ga_trace.csv`), G3 `g3_improvement_by_class` (paired improvement vs `FCFS-EAT` and vs best heuristic,
  by workload class on `test_id` and by OOD set on `test_ood`).
- `manifest.json` also records `code_hash`, a sha256 over `schedlab/*.py` at launch (there is no git repository).
- S03: raw side file `decisions.csv` (`run_uid`, `selected`, `candidates` `|`-separated, `fallback`, `novel`, the
  nine features; `NA` features for `RANDOM-SELECT` and `TRY-ALL`), one row per ok S03 run; header only otherwise.
  `runs.csv.model_id` = sha256 prefix of the selector pickle. Model directories `results/models/<name>/`
  (`selector.pkl`, `model.json`, `train_hashes.txt`, `val_hashes.txt`), read-only, never overwritten. Derived:
  `s03_robustness.csv` (per method and split: Cmax/LB mean and median, speedup, regret mean / p95 / max, share with
  regret ≤ 5%, worst class and its mean regret, median scheduling and decision time; `VBS` times are `TRY-ALL`'s),
  `s03_paired.csv` (paired statistics as §4.1, plus `gap_closed` with bootstrap CI against `SBS`; Wilcoxon only for
  `ADAPTIVE` vs `SBS`), `s03_selection_by_class.csv`. Reference columns: `SBS` (heuristic chosen on `val`, from the
  model), `VBS` (per-instance best heuristic), `BEST-FIXED-HINDSIGHT` (best mean Cmax/LB on the evaluated split itself;
  labelled hindsight). Figures G7, G8, G9 with source CSVs. Contingency extension: `[s03] model_ga`; manifest
  `models` lists each model with its `role` (`model`, `model_ga`); `s03_ga_extension_overhead.csv` (per method and
  n: median and mean measured time per call, ratio of means vs HEFT, GA-call share, paired improvement vs HEFT and
  vs `ADAPTIVE`, hypothetical τ* vs `ADAPTIVE`); `decisions.csv.selected` may be `GA-1000` for extension methods;
  `model.json.measured` holds training timings, which are excluded from `model_id`. `[s03] model_id` /
  `model_ga_id` pin the expected ids; the runner refuses a mismatch. S03 final provenance: `provenance/s03_final/`.
- S02: model directories `results/models/<name>/` (`policy.pt` weights + feature columns, `model.json` with settings,
  stop reason, updates, episodes, best update and its `val` ρ, update-0 ρ, and `measured` = training seconds and power
  source, excluded from the id; `training_log.csv`: update, episodes, elapsed_s, mean_return, batch_mean_rho,
  val_rho; `train_hashes.txt`). `model_id` = sha256 prefix over the weight tensors. Config `[s02] models` /
  `model_ids`. Manifests now record `power_at_start` (in `hardware`) and `power_at_end`. Derived: `s02_paired.csv`
  (ρ = C_RL / C_baseline per split; Wilcoxon only for the primary RL vs HEFT), `s02_generalization.csv` (Δ per OOD set
  with bootstrap CI and the §4.6 verdict), `s02_overhead.csv`; figures G4, G5, G6. S02 final provenance:
  `provenance/s02_final/`; training curves for the four final models also in `results/figures/s02_training/`.
- Provenance for a final campaign lives in `provenance/<campaign name>/`, separate from raw data:
  `EXECUTION_PROVENANCE.md` (what ran, with the exact code snapshot in `execution_snapshot/`) and
  `POSTPROCESSING_PROVENANCE.json` (analysis-code hash, commands, test result, sha256 of every raw, derived, figure and
  report file). The raw directory and its manifest are never edited.
- Raw floats are written with Python's shortest round-trip representation and must be read with
  `float_precision="round_trip"`; pandas' default parser can differ in the last digit.
- Instances are regenerated from seeds; they are not stored. The content hash in `runs.csv` detects generator drift.
- Nothing depends on Python's salted `hash()`: stable hashes use `zlib.crc32` or SHA-1, there is no iteration over
  sets where order affects results, and all ties are broken by the rules in `ALGORITHM_DESIGN.md` §1.3. The
  `PYTHONHASHSEED` value is recorded but not relied on.
- `torch.manual_seed`, `torch.use_deterministic_algorithms(True)`, one thread.
- The full parsed config, package versions, hardware and git commit are in `manifest.json`.
- Logging: stdlib `logging` to `results/raw/<campaign>/run.log`; one line per failure with the traceback.
- Error handling: an exception or timeout inside one scheduler call is caught, logged, written as a failed row, and the
  campaign continues. A validation failure is written as `invalid` and makes the campaign exit non-zero at the end.
- Resume: on restart with the same campaign directory, (instance, algorithm, seed, repeat) keys already present are
  skipped.
